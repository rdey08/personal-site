## Context

NASA's **Planetary Data System (PDS)** is the long-term archive for data from
planetary missions; its **Atmospheres Node** curates atmospheric datasets.
Archiving to PDS is only useful if the metadata is correct and complete, and
producing that metadata by hand for large datasets is slow and error-prone.
**ELSA**, the Educational Labeling System at Atmospheres, is the web
application that makes this tractable: it walks planetary scientists through
generating and archiving metadata for large datasets so the data becomes
searchable and reusable. For the Atmospheric Modeling Annex, ELSA harvests
metadata directly from netCDF model output, variables, coordinates, and
simulation configuration, so archived models stay searchable.

## What I built

- **Atmospheric Modeling Annex (frontend lead).** I led the frontend for a new
  PDS service that archives planetary **atmospheric model** data, a new class
  of archive for the node.
- **AI Assistant and Guided Bundle Creation.** Deployed ELSA's in-app
  **AI Assistant** and its **Guided Bundle Creation** flow.
- **Security features.** Added **two-factor authentication (2FA)** and
  **reCAPTCHA**, hardening access to the tool.
- **UI modernization.** Rebuilt ELSA's interface on **Bootstrap 5** for
  responsive, usable layouts across devices.

## Impact

ELSA lets scientists produce archive-ready metadata for large datasets that
would otherwise be prohibitively tedious to prepare, and the Atmospheric
Modeling Annex extends the node's archive to a new data type.
